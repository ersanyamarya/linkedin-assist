## High‑Level Architecture

- **Chrome MV3 content‑script only** – `public/manifest.json` injects the compiled script `dist/content-scripts/editable-text-area.js` into every LinkedIn page (`https://www.linkedin.com/*`).
- **DOM observer** – `src/content-scripts/editable-text-area.ts` creates a single `MutationObserver` on `document.body`. It watches for newly added comment editors using selectors defined in `src/lib/constants.ts` (`DOM.SELECTORS.EDITABLE_COMMENT_BOX`).
- **Idempotent wiring** – Each detected editor receives the attribute `data‑mutated` (`DOM.ATTR.DATA_MUTATED`) to prevent duplicate button injection.
- **UI injection** – A light‑bulb “idea” button (`linkedin‑assist__ideaButton`) is appended next to the editor row. Clicking the button starts the extraction flow.
- **Extraction & validation** –
  - **Messaging threads**: extracts sender and the last three messages, validates with `src/lib/schemas.ts` (`MessagesSchema`).
  - **Post comments**: extracts the post and visible comments, validates with `PostCommentsSchema`.
- **Prompt flow** –
  - **Messaging**: `createMessageReplyModal()` → `buildMessagesPrompt()` → `createTextModal()`.
  - **Post comments**: `createPostCommentPromptModal()` → `buildLinkedInCommentPrompt()` → `createTextModal()`.
- **Reusable utilities** –
  - **Constants** (`src/lib/constants.ts`) centralize DOM selectors, UI class prefixes, and SVG icons.
  - **Prompt helpers** (`src/prompt/prompt-utils.ts`) provide `joinSections()`, `asFencedBlock()`, ensuring consistent formatting across `src/prompt/messages.ts` and `src/prompt/post-comment.ts`.
  - **UI components** (`src/ui/components/`) supply base modal, input, and button building blocks used by `text-modal.ts`, `post-prompt-modal.ts`, and `message-reply-modal.ts`.
- **Styling** – Scoped under `linkedin‑assist__*` in `public/styles.css` to avoid clashes with LinkedIn’s own styles.

## Important Project‑Specific Conventions (from `.github/copilot‑instructions.md`)

- **Selectors live in one place** – Extend `src/lib/constants.ts` (`DOM.SELECTORS`) for any new UI locations.
- **Idempotent DOM wiring** – Always guard with `DOM.ATTR.DATA_MUTATED` before attaching UI elements.
- **Messaging sender extraction** – Prefer `DOM.SELECTORS.MESSAGING_SENDER_NAME`; avoid generic `a[href*='/in/']` which can match `@mentions`.
- **Editable‑text utilities** – Use `setEditableText()` / `ensureEnterToSend()` from `src/lib/editable-text.ts` when inserting preset replies.
- **Prompt formatting** – Reuse `joinSections()` and `asFencedBlock()` from `src/prompt/prompt-utils.ts`.
- **UI styling** – Keep inline styles minimal; rely on helpers under `src/ui/components/`.
- **Messaging presets** – Located in `src/ui/message-reply-modal.ts`; applied via `applyMessageTemplate()`.

## Additional Notes

- The repository uses **Bun** as both package manager and build tool; all scripts in `package.json` are built around it.
- **Biometric formatter** – `bun run format` invokes Ultracite/Biome; the repo prefers tabs, so preserve existing formatting.
- **Optional AI generation** – `src/background/service-worker.ts` calls a user-configured OpenAI-compatible API (via the `openai` SDK in `src/lib/ai-client.ts`) and streams replies to content scripts over a port (`src/lib/ai-bridge.ts`). Settings live in `chrome.storage.local` (`src/lib/ai-settings.ts`), edited on the options page (`public/options.html`, `src/options/options.ts`). Content scripts never read the token or call the API directly.
